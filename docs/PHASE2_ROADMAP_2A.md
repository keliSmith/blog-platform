# 路线图 — Phase 2a（Now / Next / Later）

> 配套：`docs/PHASE2_PRD.md` 的分期建议（§5）
> 受众：**技术 + 运营**对齐用。这是沟通工具，不是任务清单——只列主题与产出，不列实现细节。
> 总目标：把平台从"能用的 Demo"推进到"可信 + 可见 + 可达"的运营就绪状态。

---

## 框架说明

- **Now（本迭代，约 2–3 周）**：立即开工，范围已锁定，产出可上线。
- **Next（紧接其后，约 2–3 周）**：方向已定，开工前需补少量决策（标 ⚠️）。
- **Later（候选项，不排期）**：验证前置价值后再决定是否做。

---

## 🟢 NOW — 打地基（可信 + 可见 + 可达）

| 主题 | 对应 PRD | 产出（可交付物） | 状态 | 依赖 |
|---|---|---|---|---|
| **站内通知系统** | §4.1 | 通知表 + 列表/已读接口 + Header 铃铛 + 评论/点赞/收藏触发；创作者正循环闭环 | 🟢 On Track | 无硬依赖 |
| **SEO 可发现性** | §4.2 | 详情页动态 OG/meta（`react-helmet-async`）+ `/sitemap.xml` + `/feed/rss.xml` + `robots.txt` | 🟢 On Track | 无 |
| **后台用户管理 + 站点设置** | §4.4 | 用户列表/搜索/封禁/角色接口 + 站点设置 KV + 后台"用户管理""站点设置"两个页签 | 🟢 On Track | 无 |
| **防刷与限流** | §4.7 | 基于 Redis 的评论/文章/点赞限流中间件 + 公共接口 IP 限速 + 评论验证码（开关） | 🟡 At Risk* | Redis（Compose 已含，但需申请验证码站点密钥 ⚠️）|

> *At Risk 仅因第三方验证码密钥未申请；限流主体不依赖它，可先上线"限流 + 验证码开关默认关"。

**Now 退出标准（Definition of Done）**
- 作者能收到互动通知并能一键已读。
- 文章可被搜索引擎收录（sitemap 合法、OG 正确），RSS 可订阅。
- 运营可在后台封禁用户、改站点标题/Logo，无需改代码。
- 单用户刷评论/文章被限流拦截（429），正常用户无感。

## 🟡 NEXT — 接效率与互动（运营自助 + 资产复用）

| 主题 | 对应 PRD | 产出（可交付物） | 状态 | 依赖 / 决策 ⚠️ |
|---|---|---|---|---|
| **媒体资源库** | §4.3 | `media_assets` 表 + 上传/列表/删除接口 + 编辑器"从库选择"入口 | ⚪ Not Started | 无 |
| **相关文章 + 社交分享** | §4.5 | 相关文章接口（同分类+标签相似度）+ 详情页底部卡片（复用 ArticleCard）+ 分享面板（复制/微信二维码/X/微博） | ⚪ Not Started | 分享用外链 vs 二维码需定（微信无公众号只能二维码 ⚠️） |
| **评论增强** | §4.6 | 评论编辑（限时）+ 举报接口 + 后台举报处理队列 | ⚪ Not Started | 依赖 Now 的通知(4.1) 与限流(4.7) |
| **邮件/手机验证全流程** | §4.8 | 注册默认 `verified=False` + 验证邮件/重发（限速）+ 个人页验证徽标 + 未验证引导条 | ⚪ Not Started | SMS 仍 console 兜底（非目标），发布说明标注 ⚠️ |

**Next 退出标准**
- 作者可从媒体库复用图片，不上传第二遍。
- 每篇文章底部有相关推荐，并在详情页可分享到至少 2 个外部渠道。
- 用户可编辑自己限时内的评论、可举报违规评论，运营后台能处置。
- 新用户走真实验证流程，"假验证"字段问题修复。

## 给运营的 1 句话对齐

> 2a 让平台**"能被搜到、能被管起来、不会被刷"**；2b 让作者**"发得顺、被看到、能互动"**；2c 用数据验证这一切是否真有效。

## 给技术的 1 句话对齐
